## 2. 值得抄的：**元数据化的部件表**（这是它真正的设计）

它每个部件的定义长这样（字段名是它的，值是我们该有的）：

```js
J.register('layout', 'myKey', {
  name:  '日本語の短い名前',        // UI 里显示
  tags:  ['pop', 'graphic'],       // 适合什么情绪/题材
  w:     1,                        // 基础抽取权重（0.4–0.7 冷门 / 1.2–1.5 通用主力）
  fits:  (n) => n <= 12,           // **适用条件**：字数超了就抽不到它
  plan(rng, cut, st) { … },        // 用 rng 决定这一次的具体参数（确定性！）
  render(env) { … },
}, 'packName');
```

三个字段值得直接搬进我们的 `src/shots/`：

| 字段 | 它的作用 | 我们对应什么 |
|---|---|---|
| `tags` | 按情绪/题材筛（`glitch calm pop graphic editorial emotional horror`） | `use` / `energy` / `avoid`（我们已有 `anim shots --use` 的雏形，但没有"情绪"这一维） |
| `w` | 抽取权重：冷门部件少出现、主力部件多出现 | 我们**完全没有**：11 个模板一视同仁 |
| `fits(n)` | **适用条件**（字数、行数、是否有图） | 我们**完全没有**：模板不知道自己适不适合这段内容 |

**为什么这条最值钱**：我们现在的"选模板"是模型读了 `anim shots` 的输出后**凭感觉挑**；
它那边是"先按条件筛，再按权重抽"，**模型只写内容、不负责选型** —— 正好对上 `HANDOFF-directions.md`
那句"把审美从模型手里拿走"。

## 3. 值得抄的：**`pack` 单文件、只注册、不改核心**

它加一个表达 = 新建一个 `src/11p_<pack>.js`，里面只有 `J.register(...)`。
核心文件（planner / render / export）**一行都不用动**。

对我们的意义：`src/shots/` 已经是"一个模板一个文件"，但**登记要改 `index.js`**（手写清单）。
`1-48` 扩到 20+ 模板时，这个清单会成为合并冲突的热点 ——
**改成 `import.meta.glob` 自动收集 + 每个模板自报元数据**，加模板就真的只加文件。
（`tools/test-shots.mjs` 现有 129 项，正好可以改成"扫目录断言元数据齐全"。）

## 4. 值得抄的：**绿幕 / 透明导出**

它能把"背景"和"文字+演出"分成两张图导出（绿幕 / 黑底），给后期合成用。

**先登记，不排期**（对"一个人做片子"来说收益中等）。

## 5. 不要抄的（三条，都是硬边界）

1. **Canvas2D + 固定设计空间**：它的画面上限就是 2D 排版 + 贴图变形，没有真 3D、没有 HDR 泛光、
   没有多子帧运动模糊。我们的 WebGL2 栈在"质感"这一维是**高一档**的，别为了对齐它的部件数量去降级。
2. **全局 `J` + IIFE + 两兆大文件**：与我们的 ESM + 纯函数 + 判据/回归体系是两套世界观。
   它的部件之间靠 globals 互相摸，没法单测；我们搬过来会毁掉 `tools/` 那一整套。
3. **领域锁定在歌词 PV**：它的 timing 来自歌词行（LRC），没有"旁白决定镜头长度"那一层。
   `1-50` 的 `infoShot` 要的是"标题 + 旁白 cue + 图形区 + 标注 + 出处行"，它给不了。
