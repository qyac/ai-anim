# 审美与制作准则（判例式）

> 来源：**本项目自己的返工记录**。每条 = 规则 + 判例（用户原话）+ 自检问题，三要素缺一不可。
> 编号体系：R(节奏) / Q(质感·构图) / S(声音) / C(文案) / P(流程)。**编号一经发布不重排**，新增只追加。
>
> 机器能判的（卡点、事件密度、底色、一致性）已经在 `anim report` 里；这份文件管**机器判不了的部分**。
> 出片前逐条过一遍，输出 `编号 ✓` 或 `编号 ✗(位置)`。准则可以被有意违反，但要在该项目的 `FACTS.md` 里写清为什么。

## 节奏 R

### R1. 画面不许停超过 3.5 秒；要停就给「大面积、持续变」的东西
规则：任何 2 秒窗口里画面都要有可见变化；静止跨度上限 3.5 秒。补运动要**大面积**（推进、扫描带、逐条落位），
2px 游标 / 0.09 alpha 水印**不算** —— 检测器和人眼都看不见。
判例：主片 `nekohome-intro-ja` 首版稀薄窗口 43%（上限 25%），最静的四段全在「文字已到位、画面不动」的区间；
补了进度条（596px 宽）+ 120px 高的慢扫描带后降到 13%，最长静止 1.3s → 0.3s。
自检：`node tools/lint-event-density.mjs <任务>` 是否 ✓？补的运动是「大面积」还是「一根线」？

### R2. 相邻两支片子不能同一张脸
规则：连着发布的片子在**主色 / 切法 / 段序**三项里至少换两项；同一条时间线里相邻两段别用同一种镜头模板。
判例：15 支 nuomi 短片被用户一句「模版重复」打回 —— 它们主色相同、开场全是 `title`、切法一致。
改法：主色 6 色轮换 → 段序循环移位（开场变成 kinetic/scan/device/quote）→ 偶数支加 0.25s 交叠。
自检：把两支的接触表并排看，第一眼能分出谁是谁吗？

## 质感与构图 Q

### Q1. 坐标不许手算，尤其不许手算「居中」
规则：整行文字一律 `type.writeLine(..., { anchor })`；`type.write(..., { align })` 的 `align` 是**整行对齐**；
别在调用处再手减 `w/2` —— 那是双重偏移的来源。
判例：成员卡「头像和名字有一点偏移」、大标题「大标题没改！」都出在手算偏移上；改用 `writeLine` 后名字位移从 +41~80px 归零。
自检：这段里有没有 `x - 宽度/2` 这种表达式？

### Q2. 一屏只让观众看一件事
规则：一屏一个主体；主体之外 ≤ 2 块，每屏 ≤ 6 块字。要同时说两件事就切成两段。
判例：`compare` 模板默认 4 行时一屏 8 块字以上，版面守门 warn —— 那是读数不是错误，但别把它放在「必须只看一件事」的位置。
自检：`check` 的版面守门有没有 ⚠？主体声明了吗（`focus`）？

### Q3. 风格由内容决定，但一次只能一套
规则：一支片子只用一套风格包；风格里「主色 / 字体 / 母题」是介质，不是装饰，别在段与段之间换。
判例：`--style` 临时覆盖曾出现「背景不跟调色板」的假象 —— 根因是模板之间对底色 key 的约定不一致（有的读 `ink`、`chart` 读 `bone`）；
统一成 `P.bg` 后 15 套风格全绿。**结论：换风格要整片换，且底色只有一个名字。**
自检：`node tools/test-style-palette.mjs` 全 PASS？

## 声音 S

### S1. 「配了音」= 成片音轨里真的有声音，不是「生成了 VO 文件」
规则：交付前必须从 mp4 里核对音轨（存在 + 有电平 + 与源 VO 对齐），不能只看中间产物。
判例：用户「声音没配上」—— 当时 VO 文件都在、`say` 也报成功，但渲染队列还没跑完，13 支片子仍是无声旧版；
还有一半原因是段序改了而旁白没重生成（嘴在说 A 段、画面已到 B 段）。
改法：**先定段序 → 再生成旁白 → 用解出的 slot 回写 dur**，任何一边动就整链重跑。
自检：`ffprobe` 有 audio 流？`ffmpeg -af volumedetect` 的平均电平与 VO 源差多少？

### S2. 音色用我们自己的模型
规则：角色配音走 GPT-SoVITS（Cotton）；edge-tts 只做占位与对照。
判例：用户「用我们的gptsov去配音啊」。跨语种（中文台词 + 日语参考音）会有日语腔，要更稳就改写日语台词 + 中文字幕。
自检：`audio/*-vo.mp3` 是哪个驱动产出的？`ANIM_GSV_*` 配的对吗？

## 文案 C

### C1. 文案不许有 AI 味
规则：短句、具体名词、允许自嘲；**禁止**「XX 的：A，和 B」这类对仗排比，禁止每段都下结论。
判例：用户一句「文案ai味重」打回整片文案。改完的判据是：念出来像人说话，不像产品介绍。
自检：把每句念一遍；有没有两段以上用同一个句式开头？

### C2. 交付语言：**日语配音 + 中文字幕**（中文画面字）
规则：角色片默认日语人声 + 中文字幕；画面上的标题/标注仍是中文（用户明确不要日文大标题）。
判例：「字幕还是要中文啊喂」→「去掉中文版本」→「日语台词 + 中文字幕」三轮回合才定案。
**结论写死在这里**：人声日语、字幕中文、画面大字中文。
自检：`captions: true` 且字幕表是中文？画面上有没有出现日文大字？

## 流程 P

### P1. 改动必须先能自检，再谈好不好看
规则：每条「不报错但结果不对」的坑，都要补一个**机器判据**（工具/测试/钩子），否则下次一定复发。
判例：「修吧，现在主要是进化引擎，而不是做视频」之后，逐个补了 prog 区间、卡点、事件密度、底色、预览一致性、预提交钩子、CI。
自检：这次的坑，下次靠什么自动发现？

### P2. 先做能立刻验证的那一步，别一次铺满
规则：一轮只推进一个可验证的增量；出图/出片看效果再继续。
判例：这一轮从「素材库怎么扩」一路做到卡片、图标、素材层、流体原语 —— 每一步都先出图再看下一步。
自检：这一步有没有一张图/一条命令能证明它成了？

### P3. 渲染期间只写 `out/`
规则：有一场渲染在跑时，仓库里任何文件都别写（HMR 会让 Vite 崩、渲染断流）。
判例：`docs/*.md` 曾被判定为「可以安全写」，第七轮实测作废 —— 编辑器的原子写会留下 tmp 文件，照样触发 watch。
自检：现在有渲染在跑吗？
